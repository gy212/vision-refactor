# PR 描述契约（分级变更说明与实证规范，`R-WORKFLOW`）

本契约是全团队与 AI Coding Agent 编写 Pull Request 描述的按需工程规范，旨在让审阅者在 **15 秒内** 确认三项核心事实：**根因修改是否落在正确层级？旧路径是否已彻底清理？变更前后真实行为或结构发生了何种变化？**

## 1. 分级选用与交付状态边界

1. **按客观 Diff 边界选用模板**：
   - **标准版（4 节）**：适用于所有涉及业务代码、静态规则、公共接口、改变运行时行为或静态规则语义的配置变动（如 `.harness.json` 阈值/开关、`pyproject.toml` 打包/入口配置）的 PR（含纯等价内部重构；纯重构允许在 `## 2` 展示模块结构、依赖方向或静态门禁结果的变更前后对照）。
   - **轻量版（3 节）**：**仅当客观 Diff 仅修改纯文档、不改变运行时行为与规则语义的配置或纯测试资产，且无任何业务代码与公共接口变动时可用**（明确排除 `.harness.json` 阈值/开关等改变运行时行为或静态规则语义的配置改动）。
2. **明确区分 WIP 草稿与阶段闭环交付**：
   - **WIP 未完成草稿**：本阶段尚未自洽、未通过验证或存在破坏主干风险的在途 PR，**必须设为 GitHub `Draft` 状态，不可合并**。
   - **阶段闭环交付 `(#<Issue编号>, k/N)`**：当本阶段改动自身闭环、验证通过且不破坏主干时，**可设为 Ready 并评审合并**；须在 `交付范围` 标明 `分阶段交付 (k/N)`，并在 `未覆盖项与保留分支` 中逐一列出剩余范围、后续跟踪 Issue 编号与退场条件。
3. **透明清理底线**：单仓私有调用无分阶段计划时必须在单次交付内删旧（`R-SSOT`）。严禁隐藏已知未覆盖同级场景或以“维持兼容”含糊带过；确无移除旧路径、无未覆盖项或无改动旧断言时，必须显式填写`无`。

## 2. PR 与 Commit 标题规范

- **标准格式**：`<type>(<scope>): <简体中文描述>`（阶段闭环交付末尾附半角 `(#<Issue编号>, k/N)`）
  - `<type>`：统一引用 `AGENTS.md` 约定的 7 类 Commit/PR 类型枚举，本契约不重复列举。
  - `<scope>`：核心受影响的包或领域名（如 `rules`、`foundation`、`config`、`adjudication`、`specs`）。
  - **语法与长度**：使用半角圆括号 `()` 与半角冒号加空格 `: `；**冒号后中文描述正文 `<= 35` 字**（不含 `<type>(<scope>): ` 与分阶段后缀 `(#N, k/N)`）。
- **三条硬约束**：
  1. **概括本质变更，不罗列触发样本或私有函数名**：
     - 错误示例：`fix: 改了 cleanliness_rule.py 里那个 docstring 报错并删了连词`
     - 正确示例：`refactor(rules): 移除模块文档连词黑名单并保留首句校验`
     - 分阶段示例：`refactor(specs): 合并常驻工程与测试契约 (#12, 1/2)`
  2. **单一动宾主干，正文 `<= 35` 字**：禁止用逗号拼接多项细碎操作。
  3. **名实相符**：未全量接通所有同级场景时，严禁使用“全量接通”等超出实际范围的表述。

## 3. 正文写作纪律

1. **简体中文主叙与干净成品**：统一使用简体中文（保留必要英文术语、代码符号与仓库相对路径，严禁本地文件协议绝对链接），正文直接从 `## 摘要` 开始、不重复一级标题，避免把 Diff 逐行复述为流水账；**Agent 生成 PR 成品正文时严禁输出任何 HTML 注释**。
2. **禁止测试数字注水与免责套话**：严禁用“通过 N 条测试”替代行为对照（`R-TEST`），严禁写入“数字有交叉不相加、不代表全量验收、某提交前已存在”等防御性免责陈述（`R-COMM`）。
3. **变更旧断言必须说明原因**：删除或修改既有测试断言时，须在 `变更测试断言说明` 按 `原 <test_old> -> 现 <test_new>` 阐明原断言为何不合理及新断言如何对齐真实业务语义；无则填`无`。
4. **破坏性变更与回滚说明（可选）**：涉及配置字段移除、CLI 参数变化、持久化格式不兼容或高风险行为变更时，在标准版 `## 1` 增加 `破坏性变更与回滚说明` 字段（无破坏性变更时省略）。
5. **本地契约自检（`square contract-check`）**：提交前可使用 `square contract-check --type pr` 自检 PR 描述；由于合规正文禁止重复 `# H1`，`--title` 为必填参数；支持配合 `--diff` / `--changed-file` 做轻量版客观路径校验，以及 `--draft` 做 Draft 状态与 WIP 一致性校验。

## 4. 标准版模板（4 节，业务代码与公共接口改动）

**填写说明**：
- `关联事项` 填 `Closes #<Issue编号>` 或 `关联 #<编号>`（无则填`无`）；`交付范围` 填 `完整交付` 或 `分阶段交付 (k/N)`；
- `## 1` 中前四项架构键必填，确无内容显式填`无`；`破坏性变更与回滚说明` 按需填写，无则删除该行；
