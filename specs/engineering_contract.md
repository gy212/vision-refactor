# 工程与测试核心契约（通用内核与静态门禁索引）

本契约是全团队与 AI Coding Agent 的常驻工程行为准绳，明确分为两层：
1. **通用工程与测试契约内核（第 1–3 节）**：与具体语言和框架无关的工程判断准则、不良动机约束与软件测试方法论。
2. **Python / pytest 静态规则适配器层（第 4 节）**：当前仓库通过 `harness/rules/` 机械兜底的静态门禁索引；Python / CLI / AST 具体边界踩坑样例单向沉淀于 `specs/packs/python_cli.md`（样例包随目标仓库动态挂载，外部仓库未提供 `specs/packs/` 时优雅回退至第 1–3 节通用内核）。

---

## 1. 核心严谨性标准与不良动机映射

工程严谨性**唯一取决于三件事**：**核心逻辑切中本质**（在概念归属的最底层公共层根治）、**目标场景真实跑通**（真实输入输出闭环）、**关键证据准确对位**（改前错、改后对且同级场景完备）。严谨性**绝不以**检查文件次数、无关历史用例跑测数量、内部防御判空厚度或免责声明长度衡量。

| `BadMotivationType` | 可观测行为表象 | 强制动作 | 语义 ID |
| :--- | :--- | :--- | :--- |
| `DEFENSIVE_ANXIETY` | 频繁哈希校验、无范围全量跑测、堆叠空泛免责 | 四要素准入；单点验证回答即停；区分真实阻塞与理论可能 | `R-MIN-VERIFY`, `R-COMM` |
| `SYCOPHANCY` | 盲从有缺陷方案、橡皮图章审查、吹捧或卑微检讨 | 独立建模；对齐抽象层与范围；直指架构退化后果与改法 | `R-ALIGNMENT`, `R-COMM` |
| `SHORTCUTTING` | 按样本写 `if` 特判、把个体写成类、下游擦屁股 | 动手前行概念归属三问；源头抽象统一修复 | `R-ONTOLOGY` |
| `LEGACY_DUAL_TRACK` | 保留无计划 `legacy` 双轨、迁就旧调用方不删旧 | 建用一体、单一事实来源（SSOT）；按分级边界彻底删旧 | `R-SSOT` |
| `SUNK_COST` | 核心假设已证伪仍硬补状态机、复杂度失控死磕 | 最小因果/不变量检验；触发门槛即一轮熔断交出最小反例 | `R-FIRST-PRINCIPLES` |
| `COMPLICITY_METRIC_INFLATION` | 照抄实现输出写断言、保护错逻辑的毒药测试、凑数 | 业务语义独立推导预期；覆齐同级与边界；淘汰毒药测试 | `R-TEST`, `R-WORKFLOW` |
| `CHEATING_COMPRESSION` | 分号拼多句、嵌套三元、巨型推导式、机械切片、造黑话 | 将超预算视为职责发散警报；按领域职责拆分；直白短句 | `R-COHESION`, `R-COMM` |
| `WALL_PLASTERING` | `getattr(self, "_...")` 糊墙、宽泛 `except` 静默吞异常 | 仅外部边界防御校验；内部信任契约 Fail-Fast 暴露死因 | `R-FAIL-FAST` |
| `BUCK_PASSING` | 获授权后碎步索权、甩未翻译底层堆栈给人类 | 明确授权下推进至落地；仅在请示白名单内停下并人话汇报 | `R-ALIGNMENT`, `R-COMM` |

## 2. 通用工程契约内核

### `R-ONTOLOGY` 本体归属与禁止样本特判
- **区分观测样本与公共机制**：报错日志、特定输入样例只是暴露问题的观测窗口，背后对应普遍的领域规律或数据契约。
- **动手前必行概念归属三问**：1）该逻辑本质属于哪一层概念、由哪个公共契约决定？2）哪些同级兄弟场景共享同一规律？3）换一个全新同类输入，不改代码能否自动生效？
- **硬约束**：严禁按触发样本名称、ID 或字面值写条件特判；严禁把单个业务案例派生为独立类；数据或契约破损必须在源头修复，严禁在下游消费端层层打补丁。

### `R-SSOT` 建用一体、破旧立新与单一事实来源
- **单一事实来源（SSOT）**：同源数据、状态、规则或配置在系统内只计算和定义一次，严禁多处拷贝维护与末端对账。
- **建用一体与分级退场边界**：
  - **单仓私有调用**：新建公共抽象、接通全部适用方与物理删除旧路径必须在单次交付内闭环，严禁保留 `legacy` 双轨。
  - **豁免边界**：跨仓或对外公共契约允许设定明确弃用期；大规模架构迁移允许按分阶段交付（`k/N`）推进，但本阶段须自洽且不破坏主干，并在 PR `未覆盖项与保留分支` 中显式登记后续跟踪 Issue 与退场条件。

### `R-FIRST-PRINCIPLES` 第一性原理与受阻熔断
- **最小因果 / 不变量检验**：优先寻找该问题最直接、不可动摇的因果关系与业务不变量。能用单一确定规律或简洁数据结构说清的逻辑，绝不叠床架屋引入复杂多层状态机或概率拼凑。
- **受阻熔断门槛**：仅当**核心架构假设在第 1 轮验证中被证伪**，或**继续修补会导致结构复杂度失控**时，立即停手止损并整理最小可运行反例退回探讨极简替代解；常规首轮实现疏漏或局部边界错应直接自修，不得借熔断推诿常规排障。

### `R-MIN-VERIFY` 最小单点验证与回答即停
- **检查准入四要素**：执行任何核查或跑测前明确：1）待回答问题；2）最小观察对象；3）最小验证指令；4）停止条件。
- **分级验证范围**：
  - **叶节点与局部改动**：最小单点验证得出确定结论即停（无反证不扩圈），默认信任未改动基线，严禁无范围全仓扫跑、重复自检或无意义文件哈希校验。
  - **共享基座与公共契约改动**：改动底层共享基座（如本仓 L0 `foundation`、L1 `config`/`ast`）或跨模块公共接口时，除本模块单测外，须覆盖直接下游依赖方的契约回归验证。

### `R-COHESION` 单向分层、高内聚与架构预算
- **单向分层与单一职责**：严格遵守单向分层依赖、零循环导入；每个非测试模块顶部第一句话声明唯一核心职责；严禁创建或导入 `utils`、`helpers`、`common`、`misc` 杂物箱模块；`__init__.py` 仅做纯公共 API 导出。
- **预算是职责发散警报**：行数上限用于倒逼按业务领域子职责拆分，严禁以分号拼接、嵌套三元、巨型推导式或无语义机械切片（如 `part2`、`step1`、`_impl`）规避预算。

### `R-FAIL-FAST` 外边界校验与内部快速失败
- **内外分治**：仅在外部物理与信任边界（用户输入、文件、网络、CLI/Hook stdin、外部配置）做防御校验；系统内部模块间信任类型契约，严禁 `getattr(self, "_...")` 糊墙与宽泛 `except` 静默吞异常。
- **分级容错边界**：
  - **主链路与核心契约**：违规或契约断裂必须 Fail-Fast 当场抛错并保留具体死因，严禁返回伪造默认值掩盖问题。
  - **非核心旁路**：附加统计、辅助渲染或宿主生命周期钩子容错等旁路逻辑，允许在显式边界捕获可预期异常、记录明确死因后降级，不得一票否决主业务交付。

### `R-ALIGNMENT` 显式对齐、自主推进与请示白名单
- **动手前对齐**：任务含糊或存在歧义时，先对齐抽象层级与影响范围（含同级场景与待淘汰旧资产），再开工。
- **授权后自主推进与直言反驳**：获得明确目标授权后，常规读写、重构与定向验证须一气呵成推进至落地，拒绝碎步索权；发现方案导致架构倒退、破坏 SSOT 或引入特判时，用工程证据直言指出后果与替代方案。
- **五类请示白名单**（除此之外自主决策）：
  1. 非平凡的重大业务或架构方向决策；
  2. 需实质性扩大既定任务范围；
  3. 存在不可逆破坏性风险；
  4. 遇到无法自行排查的真实外部物理阻塞；
  5. 触发受阻熔断（核心架构假设被证伪或复杂度失控，须附最小反例）。

### `R-COMM` 与 `R-WORKFLOW` 跨契约衔接
- 日常对话、受阻汇报与纠错回应遵循常驻契约 `specs/communication_contract.md`（`R-COMM`）。
- 提 Issue、写 PR 与执行独立审查分别按需读取 `specs/issue_contract.md`、`specs/pr_contract.md`、`specs/review_contract.md`（`R-WORKFLOW`），日常编码严禁预读。

## 3. 通用软件测试契约（`R-TEST`）

测试的唯一目的是**独立证伪公共契约**。坚持**写测求全、跑测求准**：编写时覆盖完备等价类与真实边界，按被测领域模块单一归口（就地并入 `tests/unit/test_<domain>.py` 等领域文件，严禁按迭代轮次或临时探针新建孤立脚本，淘汰旧路径时同步删除失效测试与毒药测试）；终端执行时仅定向运行受当前改动影响的最小测试集合，回答即停。

- **双轴等价类与独立语义断言**：每次公共契约改动须覆盖**触发场景 + 代表性同级场景 + 负向/异常等价类**（每类 1–2 个高代表性样本）；期望输出由业务规律或外部协议独立推导，严禁仅断言“不崩溃 / 非空 / 退出码为 0 / 属于全集枚举”，严禁照抄被测代码输出编写保护错误特判的**同谋（毒药）测试**。
- **三大通用测试维**（Python / CLI / AST 具体踩坑样例见 `specs/packs/python_cli.md`）：
  1. **等价语法与输入变体**：覆盖同义语法、参数格式与词法包裹边界，穿透子项而非仅测表层基名。
  2. **真实外部协议与环境坐标系**：跨协议、CLI 或文件系统边界喂入真实载荷与真实临时目录，严禁自造假协议字段或用 Mock 架空核心解析器；**隔离例外**：对系统时钟、外部网络/第三方服务或故障注入等不可控外部副作用，允许以最小 Fake/Stub 隔离。
  3. **有状态组件生命周期**：缓存、持久化快照、增量跳过与会话历史须验证**创建 → 更新 → 删除/显式失效 → 连续二次重入**闭环及反序列化类型边界。
- **五条禁测红线**：
  1. 严禁设定固定条数配额（如 `Total: Exactly N tests`、`TIER_QUOTAS`）或同等价类冗余拆写；
  2. 严禁永真断言（`assert True`、`1 == 1`）与无有效校验的空壳 `test_*` 函数；
  3. 严禁零生产调用的空转自测（仅验证语言内置特性或测试内局部函数）；
  4. 严禁直读自然语言文档（`specs/**/*.md`、`AGENTS.md`、`CLAUDE.md`、`README.md`）做字面字符串断言；
  5. 严禁跨模块导入生产 `_` 私有符号（`ERROR` 级硬阻断）或 `getattr(obj, "_...", default)` 兜底探测，避免直调私有方法或篡改私有属性。**正向设计出路**：当复杂内部子逻辑确需独立单测时，应抽离为拥有独立公共契约的领域子模块，严禁机械去掉下划线伪公开。

## 4. Python / pytest 静态门禁适配器索引（`harness/rules/`）

运行 `square check .` 执行以下 13 条默认静态规则及存量迁移棘轮（开关与阈值配置见 `.harness.json` 的 `rules` 段）：

| `rule_name` | 级别 | 约束意图 |
| :--- | :--- | :--- |
| `mandatory_docstring` | `ERROR` | 非测试模块须有非空顶部 docstring 首句职责声明（仅检非空首句，不设连词黑名单） |
| `junk_drawer` | `ERROR` | 禁止 `utils` / `helpers` / `common` / `misc` 杂物箱模块或目录 |
| `pure_init` | `ERROR` | `__init__.py` 仅允许文档字符串、导入、`__all__`/`__version__` 与 `TYPE_CHECKING` 导出 |
| `mechanical_slicing` | `ERROR` | 禁止 `part2` / `step1` / `_impl` 等无业务语义的机械切片命名 |
| `fail_fast` | `ERROR` | 禁止生产代码 `getattr`/`__dict__.get` 窥探 `_` 私有属性与宽泛 `except` 静默吞异常 |
| `layering` | `ERROR` | 强制单向分层依赖（含本仓 L1 `config` 与 `ast` 双向隔离） |
| `import_cycles` | `ERROR` | 基于 Tarjan 算法拦截模块级循环导入 |
| `private_symbols` | `ERROR` | 禁止生产模块跨模块导入或访问外部 `_` 私有符号与属性 |
| `primitives_single_entry` | `ERROR` | 收敛原子文件替换（`atomic_io_allowed_paths`）与子进程调用（`subprocess_allowed_paths`）至单一授权入口 |
| `module_budget` | `WARNING` / `ERROR` | 非测试模块行数超预警线（默认 600）预警、超硬预算（默认 800）阻断 |
| `function_budget` | `ERROR` | 非测试函数/方法行数超硬预算（默认 100）阻断 |
| `anti_cheat_compression` | `ERROR` | 禁止分号拼接、嵌套三元、单行复合语句及超限推导式（>2 生成器、>2 过滤、>3 总子句或 >=3 总子句折叠在单行） |
| `test_contract` | `ERROR` / `WARNING` | 阻断条数配额、测试侧跨模块 `_` 私有导入/`getattr` 探测、永真与空壳测试；预警轮次命名、直调私有方法、直读文档、零生产空转与超长测试文件（默认预警阈值 800 行） |
| `ratchet_regression`（`RatchetEngine`） | `ERROR` | 存量代码迁移棘轮：按指纹锁定既有基线与上限（`baseline_path` / `ratchet_ceiling`），只许减债不许新增 |

> **门禁能力边界**：静态规则只兜底可机械判定的结构与形式卫生；测试等价类饱和度、业务语义独立性、防同谋（毒药）测试与架构根因合理性仍由人工或 LLM 代码审查（`specs/review_contract.md`）把关。
