# Issue 编写契约（根因界定与分级上报规范，`R-WORKFLOW`）

本契约是全团队与 AI Coding Agent 编写与分诊 Issue 的按需工程规范。Issue 的核心作用是锁定底层公共机制缺陷、收敛同级影响范围，避免四类常见问题：**标题锚定单一样本或拼接多表象**、**以下游补丁替代源头根治**、**遗漏关键结构字段**、**堆砌长篇原始日志或空泛免责陈述**。

## 1. 分级选用与核心准则

1. **按场景选用两档模板**：
   - **完整根因版（5 节）**：适用于复杂或已定位根因的 `bug`、`refactor`、`perf`、`feat`。五个二级章节、必填键与对照表列头均为强制结构，不得删减或跳过；确无内容时（如无待移除旧路径或无关联事项）必须显式填写`无`。
   - **轻量 / 待排查上报版（3 节）**：适用于纯 `docs`、`chore`、`test`、尚未定位根因的 Bug 初始上报，以及触发受阻熔断（`R-FIRST-PRINCIPLES`）时的最小反例汇报。未定位根因时允许标注`待排查`；受阻熔断汇报必附 `<details>` 最小可运行反例。
2. **源头抽象与范围收敛**：触发案例只是观测窗口，必须向上抽象到公共概念层（`R-ONTOLOGY`），在唯一事实来源（`R-SSOT`）统一修复并列出同级兄弟场景与待移除旧路径。
3. **平实中文与干净成品**：统一使用简体中文主叙（保留必要专业术语、代码符号与仓库相对路径，严禁本地文件协议绝对链接）；长日志与复现脚本按需放入底部 `<details>` 折叠块；**Agent 生成 Issue 成品正文时严禁输出任何 HTML 注释**。

## 2. Issue 标题撰写规范

- **标准格式**：`<type>(<scope>): <简体中文描述>`
  - `<type>` 7 类：`bug`（缺陷） / `feat`（新功能） / `refactor`（架构或公共复用重构） / `perf`（性能优化） / `docs`（文档） / `test`（测试） / `chore`（工程配置与杂务）
  - `<scope>`：根因或变更所在的领域包或模块名（如 `rules`、`config`、`adjudication`、`cli`、`specs`）
  - **语法与长度**：半角圆括号 `()` 与半角冒号加空格 `: `；**冒号后中文描述正文 `<= 35` 字**（不含 `<type>(<scope>): `）。
- **三条硬约束**：
  1. **主语为公共机制，严禁锚定单个样本或拼接多表象**：
     - 错误示例：`测试仓库放在 /work/test/ 下跑 square check 漏报而且 src/ 布局也没扫到`
     - 正确示例：`bug(rules): 目录忽略匹配误用绝对路径导致扫描漏检`
  2. **单一主线，正文 `<= 35` 字**：提炼唯一本质矛盾，禁止用逗号拼接多个下游表象。
  3. **表述直接**：不在标题中堆砌私有函数名或晦涩缩写，一眼辨明类别与影响域。

## 3. 外部非结构化 Issue 分诊追问准则

面对外部用户或协作者提交的非结构化 Issue，按以下三条分诊处理：
1. **只追问阻塞定因的最小缺口**：缺少复现条件、运行环境或预期行为时，仅围绕阻塞定因的缺口编号追问（最多 `<= 3` 个短问题），不强制报告者手填完整 5 节模板。
2. **可复现即由维护方补全根因**：只要已有信息足以稳定复现，由维护者或 Agent 先定位源头公共模块与同级场景清单，再转为完整根因版，不将架构分析负担转嫁给报告者。
3. **多表象按公共机制拆分**：单条上报混杂多个无关底层问题时，按公共机制拆分为独立单一主线 Issue 并相互关联，严禁打包修补。

## 4. 完整根因版模板（5 节）

**填写说明**：
- 标题填入平台标题栏，正文直接从 `## 摘要` 开始，不重复一级标题；
- 合并原冗余模块字段，统一在 `## 2. 架构归属与影响范围` 的 `目标公共层` 中写明所属架构层级与核心公共模块（统一用仓库相对路径）；
- `关联事项`、`待移除旧路径` 确无内容时显式填`无`；多子问题可在 `## 1` 内用 `### 1.1` / `### 1.2` 分节；
- `## 4. 验收标准` 控制在 3–5 条复选框，按“根因修复 → 范围收敛与清理 → 验证闭环”组织；
- 底部 `<details>` 按需提供，无附加复现脚本或原始报错时省略整个折叠块（按实际语言标注代码块）。

## 5. 轻量 / 待排查上报版模板（3 节）

**填写说明**：
- 适用于纯 `docs` / `chore` / `test`、尚未定位根因的 Bug 上报及受阻熔断汇报；
- 未定位根因时 `根因状态` 标为 `待排查`，定位后可升级补充为完整根因版；
- 触发受阻熔断汇报时，必须在底部 `<details>` 中提供最小可运行复现反例代码块；其他场景无附加证据时省略折叠块。
