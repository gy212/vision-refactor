# 代码审查契约（两阶串行门控与五维手术刀规范，`R-WORKFLOW`）

本契约是全团队与 AI Coding Agent 执行代码与方案审查（Review）的按需工程规范。审查者定位为**独立基线建模者与代码证伪者**，而非顺从型复核者或抽样形式检查者，核心防范五类审查偏差：**顺从式表决**、**受作者思路锚定**、**发现局部问题即提前收手**、**纠缠主观偏好或要求内部冗余防御**、**无决策价值的全量扫跑**。

## 1. 审查定位与适用边界

1. **局部自洽不等于方案正确**：作者的代码与描述只是待证伪假设；宏观审视架构路线，微观穿透具体实现，不因排版工整或测试全绿推定方案正确。
2. **审查对象扩展为“逐变更风险单元”**：覆盖 Diff 中全部**新增与修改函数、模块顶层语句、类与常量定义、配置文件及被删除行**，避免遗漏顶层副作用、配置错配或误删防护。
3. **低风险变更豁免**：纯文档润色、无逻辑变动的机械重命名或排版调整，豁免全套六维代码级深查，重点核查事实准确性、死链与契约一致性即可。

## 2. 两阶串行门控与逐单元证伪工作流

审查者在内部思考阶段严格按“反锚定独立建模 → 宏观路线门控 → 逐变更风险单元证伪”串行推进：

### 第一步：反锚定独立建模
在细看代码 Diff 前，仅依据任务目标独立推演理想基线：剥离历史包袱后的最简本质因果是什么？应归属哪一层公共模块？哪些同级场景须同步接入、哪些旧路径应移除？

> **上下文隔离边界与工具支持**：在单轮共享上下文中同时读取任务与 Diff 难以做到完全认知隔离。当前已实现 `square review --task-spec <任务> --diff <差异> --emit-prompt` 导出统一结构化审查提示包，可交由全新独立审查会话执行以降低锚定；后续演进方向为支持 `--issue-spec --two-stage` 实现两阶段上下文物理隔离。

### 第二步：宏观路线门控（五维手术刀与提前终止边界）
对照理想基线与第 3 节【五维手术刀】审视 PR 路线：
- **唯一允许跳过代码细节的条件**：仅当核心方向错误、抽象层级颠倒或设计叠床架屋、结论为 `驳回重构` 时，可跳过逐行实现细节，聚焦论证宏观驳回证据。
- **严禁遗漏细节提前收手**：凡结论为 `暂缓合并` 或 `准予合并` 时，严禁只指出一两个主干问题即停手，必须对 Diff 内所有变更风险单元逐一完成第三步。

### 第三步：逐变更风险单元证伪（六项通用高危缺陷维 + 复审反审）
对每个变更风险单元，逆向核查以下 **6 项通用高危缺陷维**（目标仓库存在 `specs/packs/*.md` 时动态挂载对应技术栈边界检查要点，如本仓 `specs/packs/python_cli.md`；无该目录的外部仓库优雅省略，仅执行通用六维核查）：
1. **外部协议与安全信任边界**：核对外部宿主/CLI/API 真实载荷与退出码语义、鉴权与审批权移交、多用户文件属主权限与密钥不外泄，同步推翻保护自造假协议的同谋测试。
2. **语法词法与输入等价变体**：穿透同义语法全集、参数等价形式、词法切分与引号/转义边界，防止只测表层基名漏判子项或裸子串误伤。
3. **路径坐标与过滤对偶**：核查相对根路径坐标系、扫描与过滤规则的“漏扫与误伤”双向对偶、共享配置可移植性及运行期求值时机。
4. **有状态生命周期**：凡涉及缓存、持久化快照、增量跳过或会话历史，完整走查增、改、删（显式失效）、连续二次重入四态闭环及反序列化类型边界。
5. **并发、资源与性能边界**：核查竞态与锁顺序、文件句柄/连接/子进程释放、非预期全量扫描或极端规模输入下的复杂度与资源上限。
6. **外部兼容与多步回滚**：核查持久化 schema、配置字段与对外接口兼容承诺，以及多步状态写入中途失败后的状态一致性与可回滚性。

**复审新代码反审准则**：二轮及后续复审中，上一轮验收标准仅为最低底线；凡因修补而新增或修改的逻辑，一律视同全新高危单元重跑上述六维实查，确认修补未破坏原本正常的同级场景。

## 3. 五维手术刀评审准则

| 评审维度 | 核心评审准则 |
| :--- | :--- |
| **维度一：根因定位** | **源头根治还是下游擦屁股？** 凡在消费端或展示层掩盖上游契约缺陷的，一律判定方向错误，要求回源头唯一事实来源（SSOT）修复。 |
| **维度二：抽象粒度** | **提炼共性法则还是堆砌局部特判？** 凡按触发样本或个体硬编码分支（`if sample == "..."`）的，直接否定并要求抽象至公共概念层。 |
| **维度三：演进彻底性** | **建用一体删旧还是无计划双轨迁就？** 驳回单仓私有调用无故保留 `legacy` 双轨与隐瞒未闭环；**明确放行**在 PR 中已登记跟踪 Issue 与退场边界的 `分阶段交付 (k/N)`，以及有明确周期与清理计划的外部公共契约弃用期。 |
| **维度四：复杂度控制** | **契合本质的极简解还是过度工程？** 用奥卡姆剃刀审视设计代价：存在更直接、心智负担更低的等价源头方案时，否定复杂设计。 |
| **维度五：验证独立性** | **检验真实契约还是与错代码同谋？** 不因测试全绿放弃独立判断；凡保护局部特判或断言自造假协议的同谋（毒药）测试，须与错误代码一并推翻。 |

## 4. 审查纪律与状态机映射

1. **内外分治（严禁要求内部糊墙）**：外部物理与安全边界严审防御闭环；系统内部模块间信任类型契约，严禁在审查中要求作者添加 `getattr(self, "_...", None)`、不可达兜底或空 `except: pass`（`R-FAIL-FAST`）。
2. **阻断项证据准入制**：
   - `暂缓合并` 的每条代码级阻断项（`P0`/`P1`），必须给出可触发缺陷的具体输入、调用序列或环境条件及预期/实际对照，严禁主观猜测。
   - `驳回重构` 省略代码级阻断问题清单，改为在 `## 1` 强制给出**宏观驳回证据**（下设**更简等价方案草图**、**原方案代价对比**与**涉及路径**），随后直接连续编号 `## 2. 复审验收标准`。
3. **聚焦核心缺陷与核查边界**：主观命名与静态规范交由 `square check` 裁决；非阻断优化建议仅放 `准予合并` 或 `早期意见` 下的可选 `P2` 附录。`R-MIN-VERIFY` 仅限终端跑测范围，不得用来省略对变更风险单元的逐一走查。
4. **评审结论与 GitHub Review 状态映射**：
   - `驳回重构` / `暂缓合并` → `Request changes`
   - `准予合并` → `Approve`（可按需附可选 `## 附：非阻断建议（P2）`，不阻塞合并）
   - `早期意见` → `Comment`（面向 `Draft` PR 的架构方向预审或早期风险提示，不走完整阻断裁决，可按需附可选 `## 附：非阻断建议（P2）`）
5. **倒金字塔中文输出、干净成品与结构自检**：统一使用平实简体中文，首屏直给结论，代码路径一律使用仓库相对路径（严禁本地文件协议绝对链接）；**Agent 生成审查报告成品正文时严禁输出任何 HTML 注释**；产出评审报告后可用 `square contract-check --type review <文件>` 自检首屏、四态章节连续编号与必填结构。

## 5. 输出模板

**填写说明**：
- 首屏严格保留 3 项（`- **审查对象**：`、`- **评审结论**：`、`- **核心结论**：`），不增设多余首屏行；本地无编号审查写 `# PR 审查报告`，`审查对象` 填写本地分支/提交或 `本地变更`；
- `## 1. 架构与路线评审` 仅列命中的手术刀维度（严格使用 `维度一：根因定位` 至 `维度五：验证独立性`），无宏观缺陷时用 1–2 句肯定核心设计、不画表；
- **四态章节连续编号规则**（与 `square contract-check --type review <文件>` 校验规则单源一致）：
  - `驳回重构`：`## 1. 架构与路线评审`（3 列表 + `- **宏观驳回证据**：`，下设 `- **更简等价方案草图**：`、`- **原方案代价对比**：`、`- **涉及路径**：`）→ **`## 2. 复审验收标准`**（省略代码级阻断问题清单，章节编号连续 `1 → 2`，消除跳号）；
  - `暂缓合并`：`## 1. 架构与路线评审` → `## 2. 阻断问题清单`（按 `P0` → `P1` 排序，每项必含全部 5 个子字段：`代码位置`、`问题本质`、`复现对比`、`修复方案`、`测试缺口`）→ `## 3. 复审验收标准`；
  - `准予合并` 与 `早期意见`：`## 1. 架构与路线评审` + 可选 `## 附：非阻断建议（P2）`（省略阻断问题清单与复审验收标准，无建议时省略附录）；
- 底部 `<details>` 仅在有可运行反例或实测输出时提供，无则省略整个折叠块。
