# Issue #57：公共能力复用整改与修复方案

日期：2026-11-06。状态：按用户审查反馈继续整改；本轮已明确同步录像共用一份动作识别结果。

关联：[Issue #57](https://github.com/gy212/vision-refactor/issues/57)、[PR #56](https://github.com/gy212/vision-refactor/pull/56)。本文结合已有调查、当前主分支相关调用关系及本次讨论整理。本轮只编写文档，没有修改算法或重新运行录像。

本次审查后的纠正：同步拍摄的一次练习，先确定合适的动作识别来源，产生一份次数和阶段时间，各机位和各入口共同使用。不能正面识别一次、侧面再识别一次，然后把次数相等作为姿势检查门槛。本文涉及该流程的要求已据此更新；原报告的历史现象保留。

## 1. 修复目标：把应该复用的能力真正共用起来

本次整改的核心是：**该复用的没有复用，该成为公共能力的留在了某个业务内部，职责混杂的业务逻辑又没有拆开。** 结果是各处各做一套，同一能力改一处、漏几处。

要达到的效果是：一项公共能力只维护一份，所有使用方都通过它完成相同的事情；各业务只保留自身特有的要求。以后修正某项公共能力，相关动作和入口能够一致获得修正。

整改以整个仓库的能力复用关系为主线。先全面盘点，再按实际使用关系确定修改范围。Issue #57 中的判法、计数和配图问题，是必须解决的具体案例。

完成整改需要同时满足：

- 已有公共能力得到复用；适合共用的内部能力被提取到职责明确的公共位置。
- 同一能力的重复实现和遗漏接入的旧路径得到清理，所有实际使用方完成迁移。
- 动作编排、动作识别、姿势检查、验证资格、评分和报告的职责明确。
- 同样输入、阶段、身体角色和标准下，共用检查的基础测量与判断一致。
- 合理的业务差异有明确名称、适用条件和依据，共用能力能够表达这些差异。
- 每个结论都能追到具体动作、阶段、机位和测量依据。

把重复代码搬到几个新文件、只提供一个共同入口、把多份独立判法放进同一张配置表，都不足以证明完成复用。验收还要检查实际使用关系和行为。

## 3. 每个问题的上下文和修复要求

### 3.1 相同能力在不同动作里各走一套

**场景。** 单练后手直拳、普通前后手组合、上步前后手组合，都需要检查站姿、护手和出拳。相同基础能力应当能够复用。

**现状。** 程序共用了执行入口，但同名检查的实际判法仍随整套练习改变：

| 检查项 | 上步前后手直拳组合 | 单独后手直拳／普通直拳组合 |
|---|---|---|
| 开始站姿的前手肘角 | 侧面；80°～135°；标记试用 | 正面占20%、侧面占80%；90°～135°；未携带这份资格登记 |
| 开始站姿的前手高度 | 正面；比较手腕与肩 | 双面；比较手腕与鼻尖 |
| 站距 | 量脚尖或脚跟间距，参照两面中较完整的肩宽 | 量踝距，参照单面的肩宽 |
| 脚朝向 | 比较两脚尖间距和两脚跟间距 | 比较两个脚朝向的夹角 |
| 后手直拳结束时的伸直 | 侧面；177°；检查每次对应时段是否曾伸直 | 正面占40%、侧面占60%；160°；按问题画面的占比判断 |

同样约85°的肘角，在固定相同阶段的模拟检查中，上步组合接受，普通组合、单独后手直拳和实战式报问题。同样的手腕位置，也会因参照肩膀还是鼻尖而产生不同结论。

**根因。** 一部分公共能力被绑定在上步组合内部，其他动作继续使用另一套处理。动作名称同时控制分段、检查清单、测量方法、参数和验证资格，还影响考试逐次评分。改动的影响范围难以判断，共用能力也难以被其他业务正确使用。

**修复要求。** 盘点所有动作及入口的同类能力，优先复用已有实现，再提取适合共用的内部能力。单练和组合引用共同的基础动作与检查；组合另外表达顺序和衔接要求。测量、判断和适用范围各有清楚定义。

例如，“测肘角”可以供准备站姿和出拳伸直共用；这两种检查使用不同标准是合理的。“腕与肩”和“腕与鼻”测量的内容不同，需要分别命名并说明用途。已有差异逐项按教师标准和批准记录处理，不能因为名称相近就直接统一数值。

**验收。** 每项公共能力都列清所有使用方，迁移后只有一份标准实现；相同条件下得到一致基础结果，必要差异能查到依据。修改一次公共能力，各使用方都能获得修改。

### 3.2 验证资格与业务规则混在一起

**场景。** 一项检查需要说明是否正式启用、是否试用、在哪种模型和阶段验证过。

**现状。** 登记这些状态的处理还会删检查项、改名称、改标准和决定机位。上步组合的状态登记因此同时承担了规则定义和动作清单管理。

**影响。** 调整“是否试用”时，可能同时改变检查内容；复用某项能力时，也容易把原来只对某种模型、阶段有效的验证结论一起带过去。未携带资格信息，也不能视为已经验证合格。

**修复要求。** 资格登记只记录使用状态、验证范围、原因和证据。检查内容由共用规则定义，练习使用哪些检查由其业务要求确定。两种姿态模型 `full`、`heavy` 以及不同阶段分别记录资格。

**验收。** 改变启用或试用状态，可以影响是否执行检查及显示的状态标记，但不能顺带改变该项测量方法、身体部位或技术标准。复用实现不会自动获得其他模型或阶段的验证资格。

### 3.3 计数把放手当出拳，计数冲突又影响无关检查

**场景。** 正面和侧面拍摄同一次练习，系统需要识别动作，并判断两路画面对应的是不是同一次动作、同一阶段。

**现状。** 普通后手直拳的识别主要依据手离开护位再返回的距离变化。模拟输入中，仅向下放手再收回，也被两路各算作一次出拳。向前和向下移动没有被充分区分。

两路计数不同后，失败原因又传给多项检查，连开始站姿的肘角、膝角也可能无法判断。#56 已解除部分单面检查的限制，但后手直拳里的同名项目仍可能依赖两路共同判断。

**修复要求。** 同步录像共用一份动作次数与阶段时间。先按动作机位要求和必要点的可见性选择来源，再执行一次识别；其他机位按同一时间取自己的画面和关键点。识别结果供练习、考试、批量分析共同使用，姿势检查只受实际数据依赖影响。

- 优先核对已有“向前伸拳与向下放手”的识别能力，拆出可复用部分，供适用动作使用。
- 识别出拳与判断拳打得是否合格分开。弯肘、拳偏低、没有正确收回的拳，也要保留被识别和检查的机会。
- 保存唯一来源、选择依据、动作次数及起止时刻。不得先识别两遍再比较次数、选择次数多的一路，或按姿势是否合格选择来源。
- 各项检查使用共享阶段内本机位的有效数据。需要两路原始测量的项目，核对同一时间是否有实际所需数据；缺时段或缺点仍说明原因，不靠另一机位补造测量。
- “主要从正面判断”仍可能需要侧面提供参照或时间信息，实际数据需求必须写清。

**验收。** 对照纯放手、正常出拳、不规范出拳、未收回、连续多拳、遮挡和缺帧录像。计数与人工记录逐次对照；即使两路画面单独识别会产生不同数量，实际生产流程也只识别所选来源一次，各入口共用同一结果。缺少实际阶段覆盖或测量点时仍不能判断。

### 3.4 图片方向、时刻和标记部位与判断依据脱节

**场景。** 教师需要根据报告图片核对“哪里有问题”。图片必须能够解释对应结论。

**现状。** 一次已重现的前手肘角检查中，侧面占判断依据的80%，保存了正面和侧面各三张图，报告却只展示正面两张。原因是正面先保存，展示时直接拿前两张。

测量与报告还分别维护身体部位：左式前手肘角实际测左肩、左肘、左腕，图上却把两条胳膊都标红。部分检查也没有对应的标记定义。

**根因。** 判断依据没有完整传递给报告，展示端另外维护一套选择和解释办法，形成重复定义。

**修复要求。** 评估结果统一携带具体检查、动作次数、阶段、机位、测量部位、画面时刻和证据用途。报告据此选择代表图并标记，界面与导出报告共用这些信息。区分支持结论的画面和仅供对照的画面。

**验收。** 最终报告使用能够支持结论的机位与时刻，标记实际检查的身体部位；单面检查和真正需要双面证据的检查分别满足各自需求。即使只有一路发现问题，也不会被另一面先保存的图片挤掉。

### 3.5 合并提醒后，结束阶段的图片丢失

**场景。** 同一动作在过程和结束时都出现同类护手问题，报告将其合并，方便阅读。

**现状。** 过程图片在前，结束图片在后；合并后仍只展示前两张。模拟对照中，过程有第10、11、12帧，结束有第20、21、22帧。合并前两个阶段都有图，合并后只展示第10、11帧，却仍写着两个阶段都有问题。

**根因。** 多个阶段的结果被压成一条记录，下游失去了按原始成员选择证据的能力。列表里还保留图片引用，不能保证图片最终展示出来。

**修复要求。** 保留每条原始检查及其阶段、结论、证据和教师复核状态，再组合展示。各阶段先选能说明结论的代表图，再应用图片数量限制。图片不足或被省略时明确说明。

**验收。** 两阶段都有证据时，最终报告各有可辨认的代表图及阶段说明；不能拿过程图代替结束图。合并展示不改变原始检查数量和判断，不把撤销或不同复核状态混成同一结论。

## 5. 公共能力怎样复用

全库盘点尚待实施，已确认的问题主要来自上述评估与报告链路。盘点按“完成同一件事”查找复用关系，同时检查已有公共能力、业务内部能力和重复实现，不只搜索相同函数名。

| 能力 | 统一复用的内容 | 各业务保留的要求 |
|---|---|---|
| 数据与画面有效性 | 身体点位是否有效、画面时刻、坐标与尺度处理 | 本业务实际需要哪些数据 |
| 基础身体测量 | 肘角、手腕高度、脚间距等测量，以及所用部位与参照 | 哪项检查使用哪种测量 |
| 基础动作识别 | 适用动作的起动、出拳、回收等识别能力 | 直拳、摆拳、腿法各自的动作特征 |
| 阶段与时间对应 | 每次动作、各阶段及不同机位之间的对应关系 | 组合的顺序、衔接和所需阶段 |
| 姿势检查 | 相同技术要求的判法、数据需求和结果解释 | 明确记录的标准差异及适用条件 |
| 多次结果汇总 | 保存各次结果、按明确要求汇总并保留来源 | 具体检查采用的汇总要求 |
| 验证资格 | 资格记录方式、验证范围、证据及原因 | 某模型、阶段、拍摄条件的实际验证结论 |
| 结果与证据 | 判定、机位、部位、阶段、代表画面和复核记录 | 界面、文本、HTML等不同展示方式 |
| 考试评分 | 已有评分能力及其需要的动作范围 | 整段或逐次评分等明确考试要求 |

优先使用仓库已有公共能力，缺少时再按业务归属提取。公共位置应当职责清楚、符合现有依赖方向，避免成为放各种逻辑的杂物箱。业务通过公共能力组合工作，迁移后清除对应重复实现。

练习、考试和批量分析共用适用的基础能力，但输出可以不同。目前练习会合并正侧判断，考试和批量分析会分别报告各视角结论；规则提示不直接折算为考试分数。需要核对的是共同部分的一致性及各自业务结果的正确性。

## 6. 修复步骤与每批交付

按公共能力的完整使用关系分批推进。每批都覆盖该能力的实际使用方，并形成可独立审查的修改。

| 步骤 | 要完成的事情 | 交付及完成条件 |
|---|---|---|
| 1. 全库复用盘点 | 梳理已有公共能力、可提取的内部能力、重复实现和职责混杂处；覆盖全部动作、阶段、左右式、出拳手／护手及模型 | 一份能力清单，逐项写清用途、现有位置、所有使用方、共用去向、合理差异及已知限制 |
| 2. 公共能力迁移 | 优先复用现有能力，拆分混杂职责，完成对应使用方接入；分离规则定义与资格登记 | 每批列清迁入的使用方和移除的重复路径；保持行为的整理与有意改变判法的修改分别说明 |
| 3. 修复识别和检查依赖 | 在共用能力上解决放手误计、事件与阶段对应、计数冲突影响范围 | 人工次数与程序逐次结果的对照；每项无法判断都能说明具体缺少什么 |
| 4. 打通结果与展示 | 使用统一保存的判定依据，修复机位、时刻、部位标记和合并提醒 | 可打开核对的最终报告；逐项对应原始结果及图片，保留阶段与复核来源 |
| 5. 综合验收与原记录追查 | 对受影响动作、入口和历史记录做必要验证；找到原材料后复查19项无法判断 | 修改前后对照、测试结果、真实录像证据及仍未解决的项目 |

步骤2建立的结果与证据约定供后续共同使用；涉及其使用方时同步迁移，避免留下两套长期并行的业务实现。相关改动按职责拆成独立或有依赖关系的 PR。

每批交付说明：改了哪项公共能力、哪些地方复用它、哪些结果应当变化、实际变化是否符合预期，以及还存在哪些限制。

## 7. 已有决定与兼容要求

1. **保留已批准的适用范围。** 上步组合已有前手肘角下限80°、膝角上限175°、出拳齐肩容差15°的决定，并有试用安排。迁移时准确保留来源和范围。推广到其他动作属于单独的业务决定，不能随公共实现复用自动推广。
2. **验证资格单独成立。** 复用能力不能自动继承另一模型或阶段的资格。正式启用仍需真实可判正确样本误报率不超过10%、目标缺陷检出率不低于70%，且缺陷样本至少来自两名执行者。已批准的试用保留明确标记和限制。
3. **如实保留证据不足。** 来源未识别到阶段、本面未覆盖该时间或缺少所需点时，说明具体原因。不能取两路次数较大值、借用另一面的关键点、放宽判定门槛或把无法判断改成通过。时间同步由调用入口的同步录像契约提供，不通过比较两路动作数量证明。
4. **避免把不同业务强行塞进一条专用流程。** 普通后手直拳不能因为想复用某项能力，就被要求出现完整前后手组合，或意外切换考试评分方式。复用其共同能力，各自保留动作要求。
5. **历史记录保持可读、可追溯。** 保持现有用户数据、配置和成绩格式兼容，包括练习历史 `schemaVersion=1`。旧记录保留当时的结果与规则信息；缺失信息明确标为未记录。重新分析保留可区分的新结果，原报告可继续核对。
6. **算法变化有单独依据。** 公式、阈值、计数和多次结果汇总的改变，单独提供真实样本及前后对照。不能用批量更新预期结果掩盖未解释的变化。

## 8. 怎样验收

### 8.1 验收复用是否真正完成

- 每项公共能力都有完整使用方清单；原先重复实现或局部私有实现的去向可查。
- 新组合使用已有基础能力即可表达共同部分，不再复制一套测量和检查逻辑。
- 修正一项公共能力，所有适用使用方一致获得修正。
- 改变组合顺序、资格状态或报告布局，不会无故改变无关测量与评分。
- 相同输入在相同阶段、身体角色、模型和标准下，共同部分得到一致结果；不同业务输出分别符合自身要求。

### 8.2 验收具体行为

| 场景 | 预期结果 |
|---|---|
| 单练与组合使用同一检查 | 相同条件与标准下基础判断一致，差异有依据 |
| 左式／右式、出拳手／护手、不同阶段 | 使用正确身体部位和适用规则，图片标记一致 |
| 纯放手、正常出拳、不规范出拳 | 分清动作是否发生与动作是否合格 |
| 多次动作、未收回、遮挡、缺帧 | 保留各次识别及证据情况，不凭空补动作或当作通过 |
| 两路画面单独识别可能产生不同数量 | 实际只识别所选来源一次，保存来源依据；各入口和机位共用次数与阶段，不产生计数比较门槛 |
| 单面检查或需要两面原始数据的检查 | 按真实数据需求判断，缺失原因准确 |
| 只有一路观察到问题 | 最终图片能支持结论，对照图不会挤掉关键图 |
| 合并过程与结束提醒 | 各阶段的原始结果、证据和复核来源保留，图片各有归属 |
| 图片达到数量上限或原录像缺失 | 明确说明省略或不可用，不能用其他阶段图片代替 |
| 练习、考试、批量分析 | 共用部分一致；各自输出、评分要求正常 |
| 历史记录与重新分析 | 旧记录可读，新旧结果及使用规则可区分 |

验证包括相关自动检查、受影响的正确示范和错误录像，以及最终报告的实际图片。错误录像可以同时存在其他不规范动作，不要求每段只错一处。`full`、`heavy` 的结果分别记录；无法判断单独统计，不能算作检出或正确通过。

运行受影响套件和仓库要求的格式、固定样本结果、有效掩码、技术契约、资格及架构门禁。覆盖范围随实际影响确定，不因“做架构整改”就无条件重跑所有录像和无关测试。固定样本结果需要更新时，逐项解释变化。

### 8.3 原报告复查与关闭条件

找到原记录后，先确认记录编号、两路是否同次拍摄、机位身份、时间信息、模型和所用规则，再将人工动作次数与程序事件逐次对照。

分别解释10项次数冲突、2项有效画面不足、7项结束站姿缺失的原因及修复结果。截图与指定 HTML 是否同次结果也要核实。

完成关闭需要：复用关系整改到位、相关使用方迁移完成、已确认缺陷通过验收、必要真实样本证据齐备、历史兼容通过。提示变少、报告全绿或已有测试通过，都不能单独作为完成依据。原材料仍缺或已知限制未处理时，明确保留对应待办。
