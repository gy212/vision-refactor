## 一、拍摄规格

| 项目 | 要求 |
|---|---|
| 录制方式 | 用本系统的学生练习模式双摄录制，不用手机或其它软件 |
| 画面 | 正面竖屏 1080×1920，侧面横屏 1920×1080，约 30 fps |
| 正面机位 | 和考场一致，正对考生 |
| 侧面机位 | **移到考生右侧**（左式时是后手一侧），和正面摄像头成 90°，正对考生身体侧面，不要在身后斜着拍；高度约在胸口；人约占画面高度七成；避开立式空调。详细摆法和检查方法见《侧面机位调整说明》 |
| 画面范围 | 上步会让人往前走半步到一步：正面摄像头里人会走近，侧面摄像头里人会向画面右边横着移动。整个过程中，从头顶到两只脚都要在画面里，四周留出余量 |
| 画面方向 | 开始录制前确认正面画面里人是正的（第一批有一部分正面录像是横的）。录制中改旋转要到下一段才生效，所以要在开录前改好 |
| 黄框 | 正面预览里的黄框要盖住从起点上步、再退回的整个范围，上步时人不出黄框 |
| 起点 | 在地上贴一个起点标记，每次都从标记处出发，做完退回标记处 |
| 人员 | 画面中只有被拍者一人；背景里没有镜子，也没有其他人走动 |
| 姿势 | 一律左式：左手、左脚在前，右手护脸 |
| 拍摄期间 | 摄像头不挪动，光线不变 |
| 成对 | 同一次录制的正面、侧面两路成对保存，不单独补拍某一路 |
| 同意 | 被拍者已同意录像用于本系统的标定与测试（由甲方负责） |

## 二、每一段的流程

**每天开拍前，逐项看一遍**（第一批录像的侧面机位在考生左后方、一部分正面录像是横的，老师的侧面照片也没按新位置拍，这些都要靠开拍前看一眼发现）：

| 检查项 | 正确的样子 | 看过打 √ |
|---|---|---|
| 系统版本 | 交付文件夹名的日期不早于 20261022 |  |
| 侧面摄像头 | 在考生右侧。请一个人在起点摆左式，看侧面预览：脸和前手朝画面**右边**，看得到胸口和护在下颚的右手；看到后背就是放错了 |  |
| 正面画面 | 人是正的（站着），不是横的 |  |
| 范围 | 上步再退回的整个过程，两路画面里都从头顶到脚都在 |  |
| 黄框 | 盖住上步和退回的整个范围 |  |
| 起点标记 | 贴好，没被踩掉 |  |
| 画面里 | 只有被拍者一人，背景没有立式空调、镜子和走动的人 |  |

**录制操作**（学生练习模式）：

| 顺序 | 做什么 |
|---|---|
| 1 | 学号填被拍者的匿名编号（T1、S1～S5 等），动作按下面的对照表选，实战式选"左式" |
| 2 | 点"开始"，被拍者走进正面预览的黄框站稳 |
| 3 | 听到系统播报"开始"后再做动作。新版本要等两个摄像头都真正开始写录像才播报"开始"，播报之前做的动作录不进去 |
| 4 | 做完后走出黄框（连续 2 秒不在黄框里自动结束），或点"结束"，听到"结束" |
| 5 | 如果弹出"开录失败"或"录制失败，请重录"，这一对作废，重新拍一遍；作废的不写进标注表 |

练习模式的动作列表里还没有新的考试动作，先按下表选最接近的（如果新版本的列表里已经有同名的考试动作，就选同名的）。这里选的动作只影响练习模式给出的问题说明，不影响录像；拍样本时不用管练习模式给出的问题说明，真正的动作以标注表为准。

| 要拍的动作 | 练习模式里选 |
|---|---|
| 实战式 | 实战式 |
| 上步前后手直拳组合 | 前后手直拳组合 |
| 上步前后手摆拳组合 | 前后手摆拳组合 |
| 上步前后手勾拳组合 | 前后手摆拳组合 |
| 上步前低鞭腿 | 前低鞭腿 |
| 原地后低鞭腿 | 后低鞭腿 |

**做动作的段**（和考试一样，从听到"开始"算起）：

| 顺序 | 做什么 |
|---|---|
| 1 | 在起点直立，2 秒 |
| 2 | 摆实战式，保持 2 秒 |
| 3 | 第 1 次：从起点上步做动作，做完边退回起点边恢复实战式 |
| 4 | 第 2 次：同上，从起点出发 |
| 5 | 保持实战式 2 秒，结束 |

- 原地后低鞭腿不上步，也做 2 次。
- 两拳连着打，不要打出去停住，也不要每拳之间回到护位停一下。

**只拍实战式的段**：直立 2 秒 → 摆实战式，保持 5 秒 → 结束。

## 三、交付

- 系统录制目录原样交付，不剪辑、不转码、不改文件名。新版本每录一对，在录制目录下生成一个片段目录 `<日期>\record_<日期>_<时间>\`，里面有：

| 文件 | 内容 |
|---|---|
| `front.mp4` | 正面原始画面（转正后，不带骨架） |
| `side.mp4` | 侧面原始画面（不带骨架） |
| `capture.json` | 这一段的真实采集记录（实际帧率、补帧与跳帧数等），我们用它核对录像是否按真实时间写出，**必须一起交** |
| `result.json` | 系统对这一段的处理结果 |

- 学生练习模式固定不生成骨架成片，正好是我们需要的原始画面。不要改用普通录制并打开"开启骨架"：那样录完会用带骨架的成片替换原始录像。
- 另附一张标注表，每一对视频一行（可以用 Excel）：

| 列 | 内容 |
|---|---|
| 片段目录 | 系统生成的目录名（`record_` 开头） |
| 人员编号 | 匿名编号，如 T1（教师）、S1–S5（学员） |
| 动作 | 用下文的动作名 |
| 类别 | A 标准示范 / B 标定 / C 错误样本 / D 边界 |
| 故意做错的项 | C 类填下文的编号，其余填"无" |
| 第 1 次教师判定 | 教师看第 1 次。C 类：故意做错的那一项做出来了写"错"，没做出来写"对"，看不清写"看不清"。A、B、D 类和对照：写"对"。另外看出的其它错误，用下文的编号写上，如"C42 错"；判断时以老师看到的为准 |
| 第 2 次教师判定 | 同上，看第 2 次 |
| 备注 | D 类写 D 编号；其它要说明的情况（如中途有人入画） |

- 视频不进 git 仓库。收到后放在仓库外的固定目录，路径登记进样本清单。

### C 错误样本

规则：
- 每段只故意做错一项，其余要领保持正确，**两次都做错**。
- 每一项至少 2 人，各拍 1 对。"只提醒"的项也拍 2 人：系统上线一项检查，至少要有 2 个人的错误样本来验证。
- 每个动作另拍 2 对完全正确的作对照（2 人各 1 对），见本节最后一张表。
- 表里"判定"一栏的"必须识别"是要扣分的错，"只提醒"是不扣分但要告诉学生，都来自老师的答题卷和标准表。
