# 直拳伸肘增加容错

客户确认报告 `16_后手直拳_练习分析报告(1).html` 中的后手直拳正确，希望减少伸肘误报。原规则量侧面肩、肘、腕形成的大小臂夹角，每次出拳最伸展时达到 177° 才不提示，相当于距 180° 只留 3° 余量。

报告记录 ID 为 `ad7b50535ccb4db58d65aac37c0aeb83`，版本 v5.14。该次结束窗口有 4/4 个有效帧，角度范围 139.50°～168.10°，中位数 160.31°。当前算法已经按同一次拳是否伸展到位判断，不会仅因窗口里的出拳、收拳画面较弯就否定已达到的伸展。

## 最终调整

- 下限从 **177° 调整为 168°**，容差从 3° 增至 **12°**。
- 这是本次试用参数，不把 168° 写成新的教师标准，也不宣称人体真实肘角就是识别值。
- 参数属于基础直拳，前手、后手、普通组合及上步组合共用；练习、考试和 batch 使用同一规则。
- 默认参数、报告标准及试用说明同步引用公共值，规则版本更新至 v5.15；该项继续试用。

最初候选下限为 165°。缓存验证发现它会漏掉一段已有弯肘样本，其最大测量值为 167.01°，因此最终选择 168°。客户记录的最大值 168.10° 高于新下限，按原记录数值不再提示该项；它只比下限高 0.10°，不能保证换录像或重新识别后仍得到同样结果。

## 针对性验证

仅回放三个真实样本的已有 full 姿态缓存。同一当前代码、相同缓存分别应用 177°、165°、168°，不重新推理。

教师示范仍为 37 项未发现问题。两段错误样本保留原来能检出的弯肘；不能把样本中其他手臂未提示的结果算作正确检出，也不以这三段材料证明总体准确率达标。

自动化测试用 168.10° 与 167.01° 的受控姿态，贯通前后手、单拳及组合的练习、公共规则、考试报告和 batch；同时保留缺点、逐次伸肘的已有回归。定向及核心门禁共 **108 项通过**；7 条警告为已有源码体量预警。Ruff 按仓库要求的 100 列检查，空白检查通过。
