# Issue #57：审查补修与共享动作结果

日期：2026-11-07。对应PR #59、#60。本文记录用户纠正方向后的第一轮补修；后续复审发现的覆盖与保存缺口，以及最新原片验证，见[复审修复与原片验证](Issue57_复审修复与原片验证.md)。本文的v5.12测试结果保留为历史。

## 1. 同步录像只识别一次动作

**上下文。** 上一轮把两套识别算法合在一起，却仍让正面、侧面各识别一次，再比较次数、对应峰值。连续4次和2次的区间还能合并成相同长段，造成规则错误放行。用户明确指出：同一次动作应共享识别结果，不能继续把两路次数比较当作检查前提。

**现在的行为。** 先按动作机位策略和必要点可见性选一路，识别一次，形成一份动作次数及阶段时间。练习、考试、批量和各机位使用这份结果。其他机位只取对应时间的自身关键点，不再检测另一份次数。

| 动作 | 来源选择 |
|---|---|
| 普通直拳、腿法 | 侧面优先，必要点可见性不足时考虑正面 |
| 摆拳、独立站姿 | 正面优先，必要点可见性不足时考虑侧面 |
| 上步前后手直拳组合 | 保持既有侧面计时要求，缺侧面仍不能识别该组合阶段 |

是否可用沿用既有最少有效帧和有效比例。均不足时只选必要点可用帧较多的一面尝试一次，阶段找不到仍保留缺失。来源在识别前决定；不会先识别两遍择多，不按姿势是否合格选源，也不会识别为零后换面再找。

同步时间沿用录像入口契约与原帧号／fps，考试裁片保留原起点。移除了动作峰值估偏移、两路事件配对和计数一致门槛。缺少同一时段覆盖或所需有效点仍无法判断，双面原始测量仍必须有实际同采集时刻的数据。上步已有的各面稳定站姿取样保留。

结果保存所选机位、必要点、每面可见比例、选择依据、动作事件与阶段实例。文本、HTML和Tk只展示一份共用动作记录。旧历史记录继续解释其当时保存的事实。

## 2. 练习、考试、批量使用同一份完整证据构建

**上下文。** 站距等检查用到两面的测量，上一轮却只在练习出口补侧面参照。考试和批量输出只有正面引用，没有完整时刻与来源，不能解释实际依据。

**现在的行为。** 公共证据构建一次负责检查详情与原画面目录，各入口都消费它。记录含原帧号、原时刻、动作次数、阶段、实际测量点、时间来源；必要参照通过`referenceFor`指向同采集时刻的主图。考试和批量最终检查记录及JSON也保存这些信息。

原练习专属的补参照路径已删除。缺另一面、缺对应时刻或缺必要点时，不生成参照，也不把不可判定变成通过。公开练习、`judge_views`、考试`rule_reports`和实际`compare_dual_streams`出口已共同验证。

## 3. 图片名额先覆盖各阶段、各次的关键依据

**上下文。** 虽然合并提醒已保留成员，但原选图先拿过程问题图和过程对照图，剩余两张名额仍会把结束问题图挤掉。整份报告里前面卡片的附加图也会产生同样影响。

**现在的行为。** 公共选择先安排各原检查、各次动作的首张问题图及必要同采样参照，然后才安排另一问题视角、对照图或重复图。HTML按这个共同顺序分配整份报告的图片名额，再按卡片排版；Tk使用同一选图依据。仅用于观测的画面，其参照不会获得问题图优先级。

预算2张时保留过程侧面`side:10`和结束侧面`side:20`；默认12张名额已用10张时同样保留。还覆盖多次数、跨卡片、同帧不同检查和参照匹配，省略项仍有说明。

测试集存在重叠，不能将各行相加成独立用例数量。没有重跑全部560个差分场景，没有覆盖旧基准，没有重新进行姿态推理。

**普通后手直拳的实际变化。** C13和C14在识别前因必要点覆盖选择正面，仍各识别1次，判断、测量和窗口不变。C12仍未识别出拳；侧面开始站姿改用正面的1.667～1.867秒，原来独立选的是2.167～2.367秒。开始膝角因此从无法判断变为疑似问题：该侧面窗口7帧中6帧有效，5帧超出原标准。其他变化均为站姿取样时间和对应测量，没有修改阈值，也不据此新增验证资格。

最终两份报告已由正式接口生成，C35仍为26个证据框、12张嵌图和14处省略。6张原来因预算缺失的其他检查首图进入报告，替换6张同阶段补图；过程和结束各有代表。已目视核对全部实际嵌图及C12原片同时间膝角标记。C12测量接近原170°门槛，仍为待教师确认的候选，不把代码结果当作新增教师认可。

自然放手片段原来两面各选结束站姿，现在使用来源时间，所以数值有所变化。片段均不包含“放下再抬回”，不能宣称该完整动作的真实录像验收已经完成。
