# Issue #57：复审修复与原片验证

日期：2026-11-07。对应 PR #59、#60，规则版本 v5.13。本次处理复审发现的两处缺口；上一轮记录保留作历史，最新结果以本文为准。

## 1. 缺失一次动作，不能由相邻动作代替

**问题上下文。** 动作已经只识别一次，但覆盖检查仍把各次动作压成时间范围，再允许前后相差0.4秒。侧面有4次、正面缺第4次时，正面第3次可能被当成第4次的画面，检查仍输出“未发现问题”。只在练习报告处拦截，也保护不了考试和批量。

**修复后的行为。** 公共时间层按来源记录的“动作、阶段、第几次、开始和结束时间”，逐一检查各面是否真有对应画面。相邻动作不能补位；阶段内部断片、只剩部分画面、整次缺失都会保存具体原因。不同帧率允许正常采样边界差异，但不能用容差补出不存在的画面。旧0.4秒字段仅为兼容保存配置保留，不再用于这项检查。

公共规则引擎使用同一份覆盖结果。练习、单面规则、考试和批量都能说明“哪一面、第几次、哪个阶段不完整”，保留已有测量和可用次数的证据。只依赖完整机位的检查继续判断；不要求每项检查都依赖两面。停用资格和缺关键点的原因保持原有口径。

来源仍在识别前按动作机位策略和必要点可见性选择。没有重新引入两面独立识别、比较次数或按结果换源。姿势阈值、既有站姿取帧规则未改。

**复现结果。** 原审查脚本直接复跑：正面缺第4次击出画面（1.467～1.567秒）时，记录明确保存该次0帧、覆盖失败，原先错误放行的4项全部变成无法判断。新增9个覆盖用例在旧版有6项失败，修复后全通过；同时覆盖中间缺段、阶段首帧缺失和不同采样率。

## 2. 所有入口保存完整共享动作记录

**问题上下文。** 上一轮补齐了检查图片，考试和批量仍只保存各项结论。共同识别时已产生的来源选择依据、完整事件和阶段时间在最终JSON中丢失；少量图片也无法还原这些信息。

**修复后的行为。** 公共动作记录负责保存动作与左右式、输入机位、来源选择依据、完整事件、阶段实例、各面逐次覆盖和缺失原因。各入口直接保存这份记录，不再各自拼装或从图片反推。

| 出口 | 保存方式 |
|---|---|
| 练习 | 结果顶层 `sharedActionRecord`；原有字段保留，兼容历史读取 |
| 单面／双面规则 | 共用一个判断入口；同次双面诊断引用同一个记录对象 |
| 考试 | 每次配对动作的首条报告保存一份记录，另一面通过 `sharedActionRecordReport` 引用该报告下标 |
| 批量 | 结果顶层 `shared_action_records`；同步双流一份，单视频先后两段各自一份 |

零事件、缺计时机位、没有图片时也保存记录。多次同名动作各有自己的记录，不串用引用。没有把整份动作记录重复塞进每条检查。

正式考试 `result.json` 与批量 `compare_results.jsonl` 的保存路径已验证；旧的检查字段和评分字段保持兼容。

从教师正确示范、C35错误示范的正侧4个原始MP4重新运行full模型，共读取2,350帧：教师每面909帧，C35每面266帧。后续入口比较使用同一批新姿态数据，避免不同推理结果干扰复用判断。

| 教师完整录像 | 2次组合、4个拳事件、12个阶段实例；37项未发现问题 | 判断不变 |
| C35完整录像 | 1次组合、3个拳事件、6个阶段实例；14项待确认 | 判断不变，完整事件保留组合外的事件 |

提前结束是对原片新姿态数据进行裁短，保留原帧号和时间，用来模拟录像不完整；不是新拍到的自然故障录像。

### 明确显示修复生效的缺帧对照

在教师新姿态数据中，只删除正面原帧579（19.3秒），保留录像完整头尾和全部侧面数据。该帧位于第2次后手击出阶段19.233～19.367秒内部。

- 旧版：仍把该阶段当成完整覆盖，37项全部“未发现问题”。
- 修复版：依赖这段正面画面的6项变为无法判断，明确指出第2次动作过程／击出阶段不完整；其余31项不变。
- 侧面的原动作事件和阶段没有变化，没有重新识别另一套次数。

这是人工删除真实新推理采样的故障模拟，不是认定原视频本来丢帧。现有批量原始序列入口按连续帧表达时间，因此这个内部不连续序列只验证练习和公共规则；批量使用上表的真实连续裁短输入验证，未伪造其时间。
